# CSQTT for Windows 3.13

Версия 3.13 синхронизирована с upstream CSQTT 2.1.9 и сетевым протоколом
`CSQTT-WIRE-3`. Старый Windows-клиент 3.12 рассчитан на прежнюю ревизию
протокола и с новым сервером несовместим.

Windows-клиент поддерживает оба режима Android-приложения:

- импорт ссылки `csqtt://` и ручные VK-хеши;
- вход в VK во встроенном защищённом окне и автоматическую генерацию/обновление хешей звонков (`auto_js`);
- развёртывание CSQTT-сервера на VPS по SSH в режимах systemd и Docker;
- парольную и ключевую SSH-аутентификацию;
- сохранение секретов через Windows DPAPI.

## Автоматический режим VK

Выберите «Автоматически (VK)», нажмите «Войти через VK» и завершите вход на официальной странице OAuth. Логин и пароль видит только VK; приложение сохраняет полученный access token в зашифрованном виде. При запуске токен передаётся Rust-ядру через stdin, а не через командную строку или журнал.

## Развёртывание сервера

Откройте «Развернуть» и укажите VPS и SSH-доступ. Linux x86_64 musl-бинарник `csqtt` лежит рядом с `CSQTT.Windows.exe` и выбирается автоматически; весь распакованный каталог можно переносить на другой компьютер. Поле можно изменить для установки другой сборки. Клиент загрузит исходный Android-установщик `deploy.sh`, бинарник и конфигурацию, затем проверит маркер `CSQTT_DEPLOY_OK`. Для пользователя, отличного от root, на сервере должен быть установлен `sudo`.

По умолчанию главный пароль разворачивается без предварительной привязки: его занимает первое успешно подключившееся устройство. Флажок «Привязать главный пароль к этому компьютеру» включает строгую привязку непосредственно при установке. Повторный деплой без флажка также очищает прежний `main_device_id`.

Нативный Windows-клиент для сервера [CSQTT](https://github.com/amurcanov/csqtt). Он использует исходное Rust-ядро CSQTT 2.1.9 без изменения сетевого протокола, поэтому Android- и Windows-клиенты работают с одним развертыванием сервера и одинаковыми `peer`, паролем, VK-хешами, TURN и obfs-настройками.

Подробное учебное описание архитектуры, порядка разработки, отладки и тестирования находится в [DEVELOPMENT_GUIDE.md](DEVELOPMENT_GUIDE.md).

## Что реализовано

- современный тёмный Windows Forms GUI с отдельными экранами туннеля, развёртывания и журнала;
- подключение по совместимым с Android ссылкам `csqtt://connect?v=2...` и legacy-ссылкам `csqtt://password@host:port`;
- тот же TURN/RTP-транспорт, WRAP-ключ, FEC и `audio`/`video` obfs, что в Android;
- выбор актуального TURN-транспорта: `udp` или `tcp_tls`;
- Wintun VPN с маршрутом `0.0.0.0/0`, DNS из `TUNCONF` и MTU, управляемым сервером;
- применение обновлённого сервером DNS без перезапуска туннеля;
- исключение peer/VK/OK/TURN-хостов из VPN-маршрута, чтобы транспорт не зацикливался;
- динамическое добавление /32 bypass-route при каждой смене TURN-серверов в режиме Auto JS;
- запуск/остановка, журнал Rust-ядра и безопасное удаление маршрутов при выходе;
- ручные и автоматически получаемые VK-хеши, `auto_js`/`vkcalls`/`legacy` auth и auto/manual captcha в ядре;
- встроенная OAuth-авторизация VK через официальный WebView2;
- установка сервера по SSH с паролем или ключом.
- три уровня журнала: минимальный, средний и полный; сырые события статистики преобразуются в потоки, объём трафика и текущую скорость.
- пакетный вывод и ограниченная очередь журнала, защищающие интерфейс от зависания при шторме TURN retry.
- скользящая автоочистка: основной журнал хранит последние 200 строк, журнал деплоя — 500.

Конфигурация, ссылка и пароль восстанавливаются при следующем запуске. Секретные поля защищаются Windows DPAPI для текущей учётной записи; файл настроек лежит в `%LOCALAPPDATA%\CSQTT\config.json`.

## Сборка

Требуются Windows 10/11 x64, .NET 10 SDK, актуальный stable Rust toolchain
MSVC и интернет для первого получения зависимостей/Wintun.

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\build.ps1
```

Результат: `publish\CSQTT.Windows.exe`. Приложение запрашивает права администратора: они нужны только для Wintun, DNS и таблицы маршрутов.

## Настройка

Перенесите с Android-клиента:

1. `Сервер` (`host:46000` по умолчанию на сервере).
2. Пароль подключения; VK-хеши можно перенести вручную либо получить автоматически после входа в VK.
3. Те же obfs, fingerprint, client IDs и число воркеров на один хеш.
4. TURN host/port только если они явно заданы в Android; иначе оставьте поля пустыми.

Либо вставьте готовую ссылку в поле `Ссылка csqtt://` и нажмите `Применить`. Если ссылка содержит `hashes`, они заменят содержимое поля VK-хешей; если хешей в ссылке нет, используются хеши, введённые отдельно.

Сервер передаёт IP и DNS через сообщение `TUNCONF`. В CSQTT 2.1.9 DNS хранится
на сервере и может меняться из веб-панели; Windows-клиент применяет повторный
`TUNCONF` на работающем туннеле. Windows-специфичной настройки сервера нет.

## Ограничения

- split tunneling по отдельным приложениям пока отсутствует;
- вложенный сервер предназначен для Linux x86_64; для ARM-сервера потребуется выбрать отдельно собранный бинарник соответствующей архитектуры;
- поддерживается IPv4-туннель, как в текущей Android-конфигурации CSQTT;
- Wintun 0.14.1 загружается с официального сайта WireGuard во время сборки и не хранится в репозитории.
